## Semgrep 兼容边界

真实工具错误包括 C++ 结构化绑定循环的 `single name expected for simple var`。原实现超过 64 条错误时拒绝整个 JSON，并将进程返回 0 误解为分析完成。现在保留有界诊断并标记失败。

增加一次保守恢复扫描：仅对工具明确标识的语法/超时源文件缺口排除对应快照路径，独立扫描其余显式路径；只接纳第二次完全无错误的结果，保留第一轮失败记录、排除数量和部分覆盖状态。未知错误、配置错误、越界路径、截断输出不作恢复。该恢复机制已有真实 Linux Semgrep 回归；真实大仓库的恢复受实际错误类型与路径结构约束。

后续诊断补全了 Semgrep 的 `Syntax error` 类型，并将初轮并发固定为 2。任务 `68ccd216-c54c-41de-9c00-f88b30ccd85c` 又暴露了数千路径超过执行器 128 参数上限的问题，C++ 层如实记为 unavailable，证据保存在 `argv-limit-summary.json`。最终改用镜像安装的固定受信 launcher 和有界目标 JSON，在原沙箱内 exec Semgrep，保留全局命令参数限制。Docker 内容边界测试严格允许这个具体 analyzer 源文件复制到固定路径，没有允许任意 COPY。

页面提交任务 `68d3e526-1ba5-4296-871d-897d330f8519`，指定 `ApplicationExeCode/RiaMain.cpp`；真实 API 已回读该路径，`investigation_mode=off`。这验证参数链路，不声称执行了模型调查。证据为 `investigation-path-api.json` 与 `investigation-path-review.png`。

2026-10-19 继续补采确认：该任务的恢复扫描实际是步骤超时。独立诊断首轮正常退出、843 条解析错误，第二轮 180 秒到期且 stdout 为空；见 `final-recovery-diagnosis.log`。500 个合成显式目标的对照中，同版本同规则默认入口耗时 34.52 秒，`scan --experimental` 入口耗时 0.47 秒，均为 500 个候选、0 条解析错误；`--project-root` 对照未改善耗时。生产适配器两轮统一使用钉死版本 1.130.0 的后一入口，仍保留单次恢复、同一沙箱和截止时间，以及完整输出/零工具错误后才接纳结果的门禁。该合成结果只验证调度开销，不代表真实仓库检测准确率。

独立复核另发现 Semgrep 的 `extra.lines` 可能仅为 `requires login` 占位。现在实际扫描始终经快照的安全读取函数回填真实起始行；路径、行号、文件身份、大小和截止时间均受校验，越界或空白行拒绝接纳，无读取上下文的解析器也拒绝占位文本。`6d123ea3-cf6b-4d09-ad7e-8d62a1591111` 旧版本任务已取消且无报告；证据保存在 `cancelled-for-evidence-*`。

孤立探测 Semgrep 1.181.0 仍能复现相同结构化绑定问题，因此没有盲目升级生产依赖。
