## 2. 当前实现层次

### 第一层：分类与策略核心

- [ ] 建立统一的分类、脱敏策略和输出场景接口。
- [ ] 未知输出场景、缺少租户密钥、策略异常或处理超限时一律拒绝输出。
- [ ] 策略结果携带可审计的策略版本或摘要。

### 第二层：脱敏与安全指纹

- [ ] 支持结构化数据和普通文本中的敏感内容处理。
- [ ] 默认只保留不可逆指纹、类型、长度和受控的最小描述。
- [ ] 同租户可稳定识别重复内容，跨租户不可关联。
- [ ] 脱敏失败不得回退为保存或打印原文。

### 第三层：边界一致性与只读审计

- [ ] 用同一接口覆盖存储、日志、Prompt、API 和导出等场景的 conformance tests，但本 Issue 不做生产接线。
- [ ] 原始证据 vault 只定义端口和安全约束，默认关闭。
- [ ] 历史 Artifact 只提供不打印秘密的只读审计能力，不执行删除或迁移。

## 3. 边界与验收

- [ ] 仅新增或修改 Issue #94 允许的 `lima/evidence_privacy/`、对应测试和只读审计脚本。
- [ ] 不直接修改数据库 schema、service、API、frontend、LLM client 或现有业务 pipeline。
- [ ] 测试覆盖嵌套 JSON、文本、异常、日志、diff、Prompt、Unicode、二进制、Base64、URL credential 和私钥。
- [ ] 测试覆盖循环、超深、超大和超时输入，确认全部 fail closed。
- [ ] 测试证明普通输出、错误信息和审计结果均不包含原始秘密。
- [ ] 运行 Issue #94 测试，并回归 `tests/contracts`。
- [ ] 完成安全 Review 后填写合并提交、测试结果、策略边界、已知限制和文件边界；不要在本任务内接生产写入路径。
