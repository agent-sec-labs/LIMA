# [Evaluation][C01] 语义检测补充指标：冻结论据与统计接线（附 Codex 实施与人工验收清单）

## Problem to solve
真模型评测（`evaluation_data/reports/platform_eval_real_glm53_2026-10-11.json`）已证明：顶层 `detection_rate` 以案例期望终态（runtime 锚定）为分母，真模型在脚本工作台评测器下结构性为 0，读不出发现层真实能力（台账 §5 补充 2 已立项）。需要一条语义层级补充指标，Fake/真模型两模式同口径可算。本 Issue 由维护者冻结全部专业判据；判据改动需维护者批准，实施者不得自行调整。

## 冻结判据（维护者 2026-10-14 定稿）

### J1 正向状态集（什么算语义命中）
- 语义命中 = 该修订产出任意 Finding，即存在目标状态属于 `UAF_FINDING_STATES` = {`semantic-supported`, `fact-verified`, `tool-corroborated`, `runtime-confirmed`, `needs-human-review`}（源码锚：`lima/uaf_orchestrator.py`，闭合集合）。实现上等价于报告修订记录的 `finding_count > 0`——与现有误报口径使用的布尔完全一致（`scripts/run_platform_evaluation.py` 中 `fp_count += int(record["finding_count"] > 0)`），保证两指标对称。
- `abstain`、`rejected`、`none` 不算命中。
- `needs-human-review` 必须算命中：它是 Diff-only 模式下正向主张的封顶降级，仍投影为 Finding；若只数 `UAF_POSITIVE_STATES`，Diff-only 运行会结构性得 0。本指标度量发现层产出，不度量证据等级。

### J2 样本分母
- 分母 = 安全案例（`non_security == false`）的 counted vulnerable 修订数。当前冻结案例集分母 = 4（uaf-direct、null-deref-direct、overflow-direct、rebind-revisable 的 vulnerable 侧）。
- fixed 侧、clean、非安全案例不进该分母（分别属于误报与非安全过滤指标）。
- degraded（不 counted）修订不进分母，需在诊断中说明。

### J3 重复计数
- 按修订计数不按 Finding 计数：一条修订多 Finding 计 1；同一修订多个目标均为正向状态也计 1。
- 每次完整评测运行产出独立报告，跨运行不做平均、不合并。

### J4 空分母
- total == 0 时 rate = null 并附诊断原因字符串，不得输出 0.0（与现有 `poc_stability` 的 null 处理一致）。

### J5 手算期望表（冻结示例）
对已封存真实报告逐条重算，必须精确吻合：

| 案例（vulnerable 侧） | observed 状态 | 命中 |
|---|---|---|
| uaf-direct | fact-verified | 是 |
| null-deref-direct | semantic-supported | 是 |
| overflow-direct | abstain | 否 |
| rebind-revisable | abstain | 否 |

`semantic_detection_rate = 2/4 = 0.5`（detected=2, total=4）。同一报告 fixed 侧语义命中 0/4 仅作参考信号，不进本指标。

### J6 模式标注
- 报告头部新增独立字段：`llm_transport`（`scripted` / `real-provider`）与 `repro_workbench`（本评测器恒为 `scripted`）。
- 真实 provider + scripted workbench 的运行，其输出与文档表述禁止称为真实 ASan / 真实运行时证据。

### J7 边界（本任务不做）
- 不改 runtime 锚定的 `detection_rate` 定义；语义指标是补充不是替代。
- 非安全过滤缺口（CWE-190 词表封闭性挡不住算术代码上的溢出假设）属 V03 专业任务，本任务只如实输出 `non_security_filter_rate` 现值。

## Proposed solution（Codex 实施）
1. 在 `scripts/run_platform_evaluation.py` 的汇总阶段新增 `semantic_detection` 块（rate/detected/total/definition），按 J1-J4 计算；不触碰状态机与合同。
2. 报告头部加 J6 两个标注字段；`--fake-llm` 与真实 provider 两种模式都填充。
3. 回归保护：新增测试以已封存报告的案例数据为夹具（或以等价合成案例复刻该表），逐项断言 J5 四行与 rate=0.5；同时断言同一输入下既有指标（detection_rate、false_positive_rate、non_security_filter_rate、experiment_convergence、poc_stability、paired_detection、llm_usage、latency_seconds）逐字段不变。
4. 空分母用合成案例（0 个安全 vulnerable counted）断言 null + 诊断。
