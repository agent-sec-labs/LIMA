# [Report][C02] 分支/版本影响矩阵：冻结论据与数据接线（附 Codex 实施与人工验收清单）

## Problem to solve
赛题评分关注"分支影响"：缺陷影响哪些 OpenHarmony 分支与版本。#286 已把影响挖掘接入档案，但缺一个按冻结判据生成、区分"历史上包含"与"验证过受影响"的逐分支矩阵。维护者已冻结三态判据（本 Issue）；工程侧负责收集固定元数据并按判据生成矩阵。判据改动需维护者批准。

**披露边界**：首个真实案例（未公开漏洞）的矩阵数据由维护者本地持有，未经披露审核不入本仓库。本任务开发与测试一律使用合成夹具（虚构仓/虚构文件/虚构 ref）。

## 冻结判据（维护者 2026-10-14 定稿）

### J1 固定分支/SHA 清单
- 每个矩阵绑定一份显式清单：目标仓、缺陷文件路径、审查基线 ref+SHA、待核对 ref 列表（分支名/tag 名）。
- 生命周期口径以 OpenHarmony release-management 生命周期公告为准（受支持/已出维护单列一列，附来源 URL 与抓取日期）。当前受支持版本线为 5.1/6.0/6.1（Release+LTS）/7.0；4.x 与 5.0 已出维护窗口（2026-10-14 核对）。清单内容维护者提供，实施者不自行增删 ref。

### J2 三态判定 + 不适用态
| 状态 | 判定条件 |
|---|---|
| `affected`（验证受影响） | 该 ref 的缺陷文件 blob 与运行时证据闭合的基线 blob **逐字节一致**（同一 blob + 同一驱动的运行时证据直接延用）；或文件为变体但维护者人工判定缺陷函数语义等价，且（可选加强）PoC 在该 ref 检出上复现命中 |
| `fixed`（验证已修复） | 该 ref 文件内容显示缺陷代码被移除/改造（维护者确认根因消除）且同一 PoC 执行清洁（无命中、无非目标异常噪声）。修复 cherry-pick SHA ≠ 原修复 SHA 时，以该 ref 自身 HEAD 文件内容 + PoC 执行结果为准，cherry-pick SHA 仅作参考字段 |
| `unknown`（未知） | 上述以外的一切：ref 不解析、blob 获取失败、变体未人工判定、PoC 未执行、环境失败。必须带原因字符串 |
| `absent`（不适用） | 该 ref 上缺陷文件不存在。单列，不计入三态分母，表述为"该分支无此文件" |

**红线**：禁止从"分支包含引入提交"（git contains / blame）推导受影响。`historical-contains` 与 `validated-affected` 是两个必须分开记录的字段。

### J3 构建配置口径
每行矩阵必须记录：ref 名 + 分支头 SHA + 文件路径 + 文件 blob SHA + 构建方式标识（target、编译数据库/快照标识、编译器、ASan 配置、桩清单版本）+ PoC 驱动标识 + 判定状态 + 判定依据（blob 一致 / 人工判定记录引用 / PoC 日志路径）+ 数据来源（fetch 日期）。缺项字段 = `null` + 原因，不猜值。

### J4 可执行参考
`scripts/check_finding_on_branches.py`（PRESENT-UNCHANGED / CHANGED / ABSENT / ERROR 四分类）是收集器输入。映射规则：PRESENT-UNCHANGED + 基线 blob 一致 → 默认 `affected`（可被人工覆盖）；CHANGED → 恒 `unknown` 待人工；ABSENT → `absent`；ERROR → `unknown`（带原因）。不自动把 CHANGED 推成任何终态。

## Proposed solution（Codex 实施）
1. 新增只读脚本（建议 `scripts/build_impact_matrix.py`）：输入 = J1 清单 JSON（含 refs、基线、可选人工判定覆盖表），调用现有 check 脚本逻辑或直接 git 只读命令收集，输出 `impact-matrix.json` + Markdown 表。
2. 人工判定覆盖表格式：`{ref: {status: affected|fixed|unknown, rationale: "...", evidence: "..."}}`，由维护者填写；脚本校验其只允许覆盖 CHANGED/未知行。
3. 测试用合成 git 夹具仓：覆盖四分类 × 三态映射、blob 一致、变体、absent、ERROR、覆盖表校验失败、空 refs 清单。
4. 不改动 `lima/impact_mining.py` 既有行为；本脚本是它下游的矩阵投影。

### 文件范围
新增脚本 + 新测试 + 输出格式文档小节。不改检测器、裁决、影响挖掘本体。

## Evidence and evaluation
