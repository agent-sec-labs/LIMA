按 C03 判据 Issue 冻结的判据，新增一个真实工作台评测入口：把已审核样本接入平台既有 analyzer / ReproWorkbench / 容器执行链，按三分类记录原始观察并按冻结规则汇总。现有 `scripts/run_platform_evaluation.py` 保持原样（scripted 评测器另有用途，C01 在其上加工）。**判据全部在姊妹判据 Issue，本 Issue 只做工程实现；判据疑问回报维护者，不自行解释。**

## Proposed solution（Codex 实施）
1. 新增样本清单文件（JSON，格式按判据 J1）+ 校验：案例 id 唯一、源文件存在于指定根、期望类别在闭合枚举内。
2. 新增入口脚本（建议 `scripts/run_real_workbench_evaluation.py`）：
   - 逐样本 × 逐冻结 PoC × 3 次调用现有验证执行链（复用 `scripts/run_openharmony_validation.py` / `lima/openharmony_validation.py` / ReproWorkbench 的既有入口，不复制实现）；
   - 每次运行记录三分类（hit / clean / environment-failed）+ 原始证据路径（编译日志、执行日志、ASan 报告文件）+ 计时；
   - 汇总输出独立 JSON（`execution: real-workbench` 头标注），指标按判据 J5：hit_rate / clean_rate / environment_failure_rate / poc_stability，空分母 null+原因。
3. 中断与重入：Ctrl+C / 超时后已完成样本的记录保留；重跑默认跳过已完成样本（`--force-rerun` 显式覆盖），禁止自动重复可能已计费的执行。
4. 测试（无网络、无真实模型、无真实容器启动）：样本清单校验、三分类归类逻辑（编译失败 ≠ clean）、3 次重复统计与 partial/stable、空分母、中断保留、跳过已完成。执行链以 Mock 替身注入。
5. 真实运行（真容器 + 真样本）由维护者发起；本 Issue 交付物只需要 Mock 全绿 + 一次本地 dry-run 演示输出。
