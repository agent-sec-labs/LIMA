# [Competition][E02] evidence bundle 离线完整性校验器（附 Codex 实施与人工验收清单）

## Problem to solve
已有 #271 的 bundle writer 会生成 SHA256SUMS.json，但接收报告的人缺少独立的离线校验命令。本任务只回答“文件是否与包内摘要一致”，不判断漏洞成立。完整性通过不能写成“漏洞验证通过”，摘要清单也不是数字签名。

## Proposed solution
新增只读脚本 scripts/verify_competition_bundle.py（如需可测试函数，放 lima/competition_bundle_verify.py），读取已有 writer 格式，不改 writer 或已封存包。命令约定：
```powershell
python scripts/verify_competition_bundle.py --bundle <bundle目录> --format json
python scripts/verify_competition_bundle.py --bundle <bundle目录> --format text
```
退出码：0=文件完整性与基本格式有效；2=完整性/格式失败；3=参数或输入目录不可读取。包内实验 status=failed 的合法包仍可退出0。

### 给 Codex 的具体步骤
1. 阅读 lima/openharmony_validation.py 的 write_validation_bundle、_platform_document；查看 tests/test_openharmony_validation.py 的 bundle 写入用例。核对现有 SHA256SUMS.json 为“相对路径→SHA-256”对象，清单自身不在清单内。
2. 读取清单时拒绝重复 JSON key、非对象、非字符串路径、非64位十六进制摘要。不把额外路径当兼容扩展默默忽略。
3. 校验每个路径：只接受规范化的相对文件路径；拒绝绝对路径、盘符、..、反斜杠形式和重复规范化路径。检查输入目录内部的 symlink/junction/reparse point，拒绝链接文件/目录，防止读取包外文件。Windows 不支持创建链接的测试明确 skip，不能伪称已验证。
4. 对目录文件集合与清单精确比较，唯一排除项为 SHA256SUMS.json；报告缺失、多余和摘要不一致的具体相对路径。以分块方式读文件，禁止执行任何文件。
5. 检查 case.json、summary.json 可解析，summary.artifact_scope=competition-validation，case_id 两侧一致；不要求所有失败包都存在 PoC、VEP或6个replay文件。
6. JSON 输出固定字段：integrity_valid（boolean）、validation_status（原summary状态或null）、case_id、checked_files、errors（具名code+相对path+说明）。text 输出相同含义；稳定排序，不打印文件内容。
7. 新建 tests/test_competition_bundle_verify.py，测试合法passed包、合法failed包、改文件、删文件、加文件、重复key、坏摘要、坏JSON、case_id不一致和路径逃逸；用临时小包，勿提交真实漏洞内容。补简短使用说明。

### 文件范围

## Evidence and evaluation
- AC-01：合法passed和failed包都可校验成功；输出明确分开 integrity_valid 和 validation_status。
- AC-02：篡改、缺失、额外文件与畸形清单返回2，列出相对路径；非法路径/链接不读取包外内容。
- AC-03：输入包任何字节不改变；不联网、不执行PoC、不读取环境密钥。
- AC-04：运行 python -m unittest tests.test_competition_bundle_verify -v；若抽取了现有代码，再跑相关writer回归，给出实测结果。
