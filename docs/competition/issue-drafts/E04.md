# [Competition][E04] 从证据包生成覆盖率与未审阅摘要（附 Codex 实施与人工验收清单）

## Problem to solve
现有summary有快照file_coverage/byte_coverage，新版platform有unreviewed_units，diagnostics有coverage gap，但缺统一展示。快照读全不能证明TU都审阅，也不能证明零漏报。

## Proposed solution
新增 scripts/summarize_competition_coverage.py，离线读取单个bundle，输出JSON或Markdown，不改包，不联网，不计算检测率。
```powershell
python scripts/summarize_competition_coverage.py --bundle <bundle目录> --format json
python scripts/summarize_competition_coverage.py --bundle <bundle目录> --format markdown
```

### 给 Codex 的具体步骤
1. 阅读 lima/openharmony_validation.py:_platform_document、write_validation_bundle，及对应bundle测试。分别读取summary中的vulnerable/fixed，不合并两侧分母。
2. 冻结输出字段：schema_version、case_id、validation_status；每侧的snapshot_file_coverage、snapshot_byte_coverage、unreviewed_units、unreviewed_count、expected_tu_count、reviewed_tu_count、semantic_review_coverage、coverage_gaps、diagnostics、field_sources。
3. file/byte比例从原字段直取，须有限数且0≤值≤1；缺失为null，不默认为0或1。百分比只在Markdown显示时换算，JSON保留比例。
4. unreviewed_units缺失与空数组不同：旧包缺字段输出null+“未记录”；存在空数组输出[]和0，但不能据此宣称完整审阅。
5. 当前包无法可靠给出总TU分母/已审阅TU数时，expected_tu_count、reviewed_tu_count、semantic_review_coverage都为null并说明原因。不要从case.translation_units或finding数量反推全部扫描范围；不新增total-known字段填上猜测值。
6. coverage_gaps仅从现有diagnostics中精确提取'coverage gap: '前缀，保留原始code，按每侧code去重稳定排序；数量表示“记录的gap种类数”，不是受影响TU数。其他诊断单独保留，不用模型重新分类。
7. summary与侧platform.json若都有同一字段：验证相同再使用，冲突失败并列出字段；不要静默覆盖。字段来源记录如summary.json#/vulnerable/file_coverage，方便核查。
8. 输入损坏返回非0，列出错误文件与字段；正常输出仅说明覆盖记录，保持原validation_status。E02未实现时仍能独立做字段解析测试，不复制完整哈希校验器；E02完成后可在文档建议先验包。
9. 新建tests/test_competition_coverage.py：完整字段、旧包缺字段、空列表、部分未审阅、比例越界/NaN、summary/platform冲突、同码去重和无finding。给出至少两份小型演示输入和输出。
