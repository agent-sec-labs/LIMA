## Problem to solve
deploy/competition/README.md 多次引用 .env.competition.example，但实查该目录只有README。部署者无法按文档获得完整示例，并容易混淆全局配置与pilot CLI配置。

## Proposed solution
补 deploy/competition/.env.competition.example，增加配置来源表和小型静态检查。本任务只整理现有配置，不改默认行为、Compose权限、检测规则或受信构建策略。

### 给 Codex 的具体步骤
1. 先读 deploy/competition/README.md、.env.example、docker-compose.yml、lima/config.py、cxx_analyzer/config.py 和 scripts/run_openharmony_validation.py。为每个拟写变量记录“解析器/Compose实际消费位置、单位、默认值、参赛建议值、适用入口”。
2. 补齐README现有快照三限额、Sidecar时间/响应/进程/内存/AST限额、Agent预算与模式配置。读取代码确认，不把README提到但实际无消费方的变量编成可用配置。
3. 默认采用不触发付费运行的状态：模型密钥留空、agent模式off、受信构建开关保持关闭；资源建议值沿用已有README，不新设计高预算。原README建议值注明是建议而非性能保证。
4. 全局应用配置与独立pilot CLI分节。特别核对CLI实际使用 LIMA_LLM_API_KEY、LIMA_LLM_BASE_URL 及模型回退；不能仅按旧Issue文本把错误变量名写进示例。
5. 每项给简短中文注释，说明单位和联动要求。provider地址、repository import path由用户填写，不放真实地址/个人路径/密码。
6. README增加使用步骤：显式将这些值合入当前部署配置，先备份已有.env，只在测试副本演示；清楚说明该示例不会自动被Compose加载。不能提供覆盖用户.env的无条件命令。
7. 添加 tests/test_competition_env_example.py。读取示例文本，不source它、不执行shell，检查无重复key、必需项与注释、关键模式的安全缺省值、文档路径存在。维护一份小型明确映射，不靠复杂正则扫描全仓推断配置语义。
8. 提交新示例前检查.gitignore是否忽略.env.*：只对该无密钥示例调整精确例外或明确git add -f该文件；不得放开所有.env文件。

### 文件范围
deploy/competition/.env.competition.example、deploy/competition/README.md、tests/test_competition_env_example.py；如必要仅精确.gitignore例外。不修改用户.env、生产配置解析器或docker-compose安全配置。
