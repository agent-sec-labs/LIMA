# 评估 structured-v2 Specialist 提示词的误报风险

## 背景

当前 C/C++ Specialist 生产流程默认使用 legacy。structured-v2 加强了证据链、反证条件和结论分级，但现有对照尚不支持把它替换为默认提示词。

## 已有对照

- 上一轮 structured 对照：负例 Finding 为 legacy 3/15、structured 8/15；正例确认 14/15 对 15/15；同驱动判别双方 12/15。
- 修正工作台快照路径后的 structured-v2 开发集复跑：有效配对 36 条（3 个案例、两版本、三次重复、两提示词；overflow-direct 整组剔除）。漏洞版运行确认 legacy 8/9、structured-v2 9/9；fixed 版语义支持 legacy 2/9、structured-v2 4/9；原始同驱动判别 8 次对 5 次。
- 所有驱动人工有效性仍待复核，开发集结果不能视作独立验收。当前证据不支持切换默认。

报告：`docs/competition/Specialist提示词拆分试点报告_2026-10-18.md`

## 后续工作

- 逐条复核 structured-v2 在 fixed 版上的语义支持，判断误报来自提示词证据链、Critic 裁决还是样本/API 契约。
- 只针对已确认的问题提出最小改动，保持 legacy 作为对照和回退项。
- 使用未参与调优的独立样本做配对评估，记录模型失败、实验失败、PoC 人工合法性和同驱动判别；不得把弃权或环境失败记作安全。
- 只有在负例误报不增加、正例有效确认和人工核验后的同驱动判别不下降、回归通过后，才讨论将新提示词设为默认。

## 验收

1. 新旧提示词及模型/预算身份可复现，旧批次原始产物不被覆盖。
2. 独立评估集上的负例误报满足原门槛，正例和版本判别不退化。
3. 人工复核记录补齐，回归测试通过。
4. 验收前，生产默认保持 legacy。
