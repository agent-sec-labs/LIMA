# LIMA 智能体漏洞挖掘平台 · 使用说明书

运行手册。所有命令在仓库根目录执行（worktree `cxx-llm-agent-detection`，
基线 HEAD `99a0697`）；宿主实测环境为 Windows 11 + Git Bash + Python 3.13.9
（仓库自带 `.venv`）。评测/扫描/取指纹等宿主命令已实际运行验证；容器构建
与运行命令取自 `.github/workflows/ci.yml`（与本仓库 CI 逐字一致），本机
未逐条重跑。完整部署参数见 `deploy/competition/README.md` 与
`deploy/competition/.env.competition.example`，架构见
`docs/AGENT_VULN_PLATFORM.md`，检测管线分析见
`docs/CXX_LLM_AGENT_ANALYSIS.md`。

## 1. 依赖环境

| 组件 | 要求 | 说明 |
|---|---|---|
| Python | 3.11+（宿主实测 3.13.9） | 依赖随仓库 venv；宿主跑单元测试与评测脚本 |
| Docker Desktop | 需 Linux 容器 | Sidecar（clang-14/ASan 工具链）与平台服务全部容器化 |
| 镜像 | `lima:local`、`lima-cxx-analyzer:local` | `docker compose build` 按 `docker-compose.yml` 的 build 段构建；测试镜像 `lima-cxx-analyzer:test` 用 §5.3 命令从 `cxx_analyzer/Dockerfile --target test` 构建 |
| LLM Provider | openrouter / deepseek / custom（OpenAI 兼容） | 仅 `--fake-llm` 演示与单元测试不需要 |

注意：五层沙箱（Landlock/seccomp）是 Linux 机制。Windows 宿主只能运行
Fake/合同层（单元测试、`--fake-llm` 评测）；真实 ASan 复现在 Linux 容器内
执行（`lima-cxx-analyzer` 镜像）。

## 2. 快速开始（零依赖，五分钟）

### 2.1 跑通平台评测（Fake LLM，无需 Docker 与 Provider）

```bash
./.venv/Scripts/python scripts/run_platform_evaluation.py --fake-llm \
  --output output/platform-evaluation.json
```

预期：打印一行有效性边界声明后退出码 0。`output/platform-evaluation.json`
含 6 组案例 × 2 版本共 12 条 revision 记录与全部指标。Fake 基线（本仓库
2026-09-11 实测）：检测率 1.0、误报率 0.0、非安全过滤率 1.0、实验收敛
1.0、PoC 稳定性 1.0、配对检测 1.0。

### 2.2 单元测试全量

```bash
./.venv/Scripts/python -m unittest discover -s tests -p "test_*.py"
```

预期（本仓库实测）：`Ran 1609 tests ... OK (skipped=23)`，约 92 秒。

### 2.3 不带 `--fake-llm` 会怎样

无 Provider 配置时脚本在任何管线工作开始前拒绝（已实测）：

```text
ProviderNotConfigured: provider-not-configured: the platform evaluation
needs a real provider for non-fake runs -- pass --provider-url and --model,
or set LIMA_LLM_BASE_URL and LIMA_CXX_AGENT_MODEL (or LIMA_LLM_MODEL);
use --fake-llm for the offline scripted run
```

绝不降级成空报告。

## 3. 导入仓库（import 目录 + 快照指纹）

平台不接主机路径；仓库通过两个入口进入：

### 3.1 管理员导入根（服务/扫描链路）

1. 在沙箱外准备只读导入树（源码 + 依赖闭包；参赛场景依赖一律离线预
   处理，`LIMA_REPOSITORY_SCAN_SOURCES=local-import`，见
   `deploy/competition/README.md` §4）。
2. 设置 `LIMA_REPOSITORY_IMPORT_ROOT` 指向导入根；此后一切引用使用
   逻辑键 `relative/path`（`lima/repository_import.py`
   `RepositoryImportPolicy`：拒绝反斜杠与越界路径，键 ≤240 字符）。

### 3.2 快照指纹（snapshot_hash）

快照身份由清单内容哈希派生，同树重灌得到同指纹（缓存、事实、实验、
报告全部锚定它）。与 CI 相同的取指纹方式：

```bash
./.venv/Scripts/python -c \
  "from lima.workspace import RepositoryWorkspace; print(RepositoryWorkspace('<仓库目录>').inventory().fingerprint())"
```

快照默认限额：普通文件 5000 个、单文件 512 KB、总量 20 MB
（`LIMA_REPOSITORY_SCAN_MAX_FILES / _MAX_FILE_BYTES / _MAX_TOTAL_BYTES`；
大型仓库放开参数组见 `deploy/competition/README.md` §1）。

## 4. 配置 .env（Provider 与智能体链）

复制 `deploy/competition/.env.competition.example` 为 `.env` 修改。最小
真实模式配置（其余项保持默认）：

```dotenv
LIMA_CXX_AGENT_MODE=required          # off | auto | required
LIMA_CXX_AGENT_MODEL=<模型名>         # 留空回退 LIMA_LLM_MODEL
LIMA_LLM_PROVIDER=custom              # openrouter | deepseek | custom
LIMA_LLM_BASE_URL=https://<provider>/v1
LIMA_LLM_API_KEY=<密钥>
LIMA_LLM_MODEL=<模型名>
LIMA_CXX_ANALYZER_URL=http://cxx-analyzer:8090
```

模式语义：`off` 零 LLM 行为；`auto` Provider 失败诚实降级（状态记
`llm-unavailable`，结果保留低等级）；`required` 失败即任务失败，绝不以
"无漏洞"冒充成功。隐私边界：`auto/required` 模式下 Provider 会收到快照内
代码片段与结构化中间产物（详见 `docs/CXX_LLM_AGENT_ANALYSIS.md`
"隐私边界"一节）；密钥、评测标签、CVE 描述与 ground truth 永不进入模型
上下文。

## 5. 跑分诊与平台检测

### 5.1 整仓扫描（分诊 + 平台链）

分诊层内置于扫描链：语义检索与种子在全仓产出线索，`LIMA_CXX_AGENT_MODE
≠ off` 时平台链（Scout→Specialist→实验→Critic→裁决）接手
（`lima/repository_scanner.py:611` `_run_platform_branch`）：

```bash
./.venv/Scripts/python scripts/scan_repository.py <仓库目录> \
  --repository-key <逻辑键> --cxx-memory auto --format markdown
```

`--cxx-memory` 接入 Sidecar（需 `lima-cxx-analyzer` 在运行，见 §5.4）；
无 Sidecar 时平台分支如实记 `analyzer-not-configured` 跳过，不影响其余
扫描结果。

### 5.2 平台配对基准（单 case / 全量）

```bash
# 全部 6 案例（12 revision）
./.venv/Scripts/python scripts/run_platform_evaluation.py --fake-llm \
  --output output/platform-evaluation.json

# 单案例
./.venv/Scripts/python scripts/run_platform_evaluation.py --fake-llm \
  --case-id uaf-direct --output output/platform-eval-uaf-direct.json
```

报告字段：`detection_rate / false_positive_rate / non_security_filter_rate /
experiment_convergence / poc_stability / paired_detection / llm_usage /
latency_seconds`，全部可由内嵌 `records` 重算；零分母指标输出 `null` +
diagnostic，绝不伪造 0/0=0。

### 5.3 容器内测试（真实 clang-14/ASan 工具链，Linux）

与 CI 相同的构建与运行方式（`.github/workflows/ci.yml` cxx-sidecar-integration
job）：

```bash
docker build --file cxx_analyzer/Dockerfile --target test \
  --tag lima-cxx-analyzer:test .

docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,size=64m,mode=0700,uid=10002,gid=10002 \
  --tmpfs /work:rw,exec,size=512m,mode=0700,uid=10002,gid=10002 \
  --cap-drop ALL --security-opt no-new-privileges:true \
  --user 10002:10002 lima-cxx-analyzer:test \
  python -m unittest -v \
  tests.test_cxx_analyzer.SourceScanContainerTests \
  tests.test_cxx_analyzer.BuildScanContainerTests \
  tests.test_cxx_analyzer.SanitizerContainerTests
```

内部双平台全量回归另使用宿主 mirror + `lima-hosttest:local` 测试镜像
（构建配方属内部开发环境，不在仓库内；参赛交付以 `lima-cxx-analyzer:test`
与 compose 运行时镜像为准）。

### 5.4 完整平台服务（compose）

```bash
docker compose build          # 构建 lima:local 与 lima-cxx-analyzer:local
docker compose up             # .env 由 compose 自动读取
curl http://127.0.0.1:18080/health   # 宿主端口默认 LIMA_HTTP_PORT=18080 → 容器 8080
```

`/health` 的 `trusted_build_context_generation_available` 仅在受信构建
fail-closed 探针全部通过时为 true（`deploy/competition/README.md` §3；
默认部署不会全部通过，需专门加固部署）。

### 5.5 性能采集

平台评测报告自带 `latency_seconds`（总/均值）与逐 revision
`elapsed_seconds`、`llm_usage`（调用数与回复字节代理）；实验台账逐轮记录
stage/exit/error_type。大规模跑批的限额放开、tmpfs/内存、并行度参数见
`deploy/competition/README.md` §1/§2 与 `.env.competition.example`
（`LIMA_CXX_AGENT_PARALLELISM` 等）。实测数字见 `性能数据.md`。

## 8. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `provider-not-configured` 拒绝 | 非 fake 运行需要 Provider：设 `LIMA_LLM_BASE_URL` + `LIMA_CXX_AGENT_MODEL`/`LIMA_LLM_MODEL`，或用 `--provider-url/--model`；只想要离线演示就加 `--fake-llm` |
| `required platform review has no configured LLM provider` | `LIMA_CXX_AGENT_MODE=required` 但未配 Provider；改配 Provider 或降为 `auto`（诚实降级） |
| Sidecar 不可用 / `analyzer-not-configured` | `LIMA_CXX_ANALYZER_URL` 不可达或未启动 `lima-cxx-analyzer`；平台分支如实跳过，启动 compose 后重试 |
| 沙箱/受信构建不可用 | Landlock ABI < 3、非预期挂载或探针缺失都会 fail-closed 拒绝；这是设计行为不放宽，检查部署是否符合 `deploy/competition/README.md` §3 探针清单 |
| 快照清单超限（大仓库导入失败） | 默认限额面向普通仓库；按 `deploy/competition/README.md` §1 放开 `LIMA_REPOSITORY_SCAN_MAX_FILES/_MAX_FILE_BYTES/_MAX_TOTAL_BYTES` 并同步放大 Sidecar 限额 |
| 大型 C++ 头文件重 TU 提取失败 | AST dump 超过 16 MiB 产品上限（实测单 TU 可达 100–407 MB）；该 TU 服务为不可用并记 coverage gap，按函数过滤的提取在 backlog |
| `.inl/.ipp/.tpp` 文件缺失导致 TU 编译失败 | 已修复：白名单在 `lima/workspace.py` 与 `cxx_analyzer/snapshot.py` 两处镜像（提交 `0ca7d13`），无需部署侧处理；若仍见此类失败请核对镜像是否为最新构建 |
| 评测报告出现 `null` 指标 | null = 分母为零，不是满分；读 `diagnostics` 字段定位 |
