# LIMA 工具性能说明

## 1. 测试环境与任务范围

性能测试使用 Expat 和 OpenHarmony 组件源码，记录任务耗时、模型调用量、沙箱实验次数及内存占用。测试包含指定目标文件的完整分析流程，以及语法检查、AST 提取等单独步骤。

Expat 任务通过本机 Docker Compose 部署的服务提交，运行环境包含 lima、cxx-analyzer、postgres 和 redis 四个容器，分别承担任务编排、代码分析、数据存储和缓存服务。任务经 `POST /v1/repository-scans` 接口启动，耗时取任务创建与最后更新时间之差。

| 测试项 | 输入与配置 |
|---|---|
| Expat 仓库快照 | 113 个文件，约 1.5 MB |
| Expat 分析目标 | `expat/lib/xmlparse.c`，8395 行，279934 B |
| Expat 模型 | deepseek-flash，关闭思考模式 |
| OpenHarmony 分析目标 | ATT、AVDTP、L2CAP 和 GAP 组件中的目标文件 |
| 语法检查与 AST 提取 | chain-probe 容器，clang-14 |
| 容器内存采集 | `docker stats`，采样间隔 5 s |

## 2. 扫描耗时

### 2.1 完整任务耗时

下表列出 Expat 两次运行的分析耗时及沙箱实验次数。沙箱实验包括为验证漏洞假设而执行的编译和运行步骤。

| 分析目标 | 目标规模 | 模型 | 任务耗时 | 沙箱实验次数 |
|---|---|---|---:|---:|
| Expat `xmlparse.c`，第 1 次运行 | 8395 行，C | deepseek-flash | 168 s | 27 |
| Expat `xmlparse.c`，第 2 次运行 | 8395 行，C | deepseek-flash | 145 s | 27 |

Expat 两次运行分别耗时 2 分 48 秒和 2 分 25 秒，均调用模型 40 次，执行沙箱实验 27 次。两次运行使用相同的分析目标、模型及编译配置，其中第 2 次运行同时采集容器资源占用。

任务耗时包含模型请求、代码分析和沙箱实验。模型响应时间、候选数量及验证步骤均会影响完整任务的执行时间。

两次运行对应任务 `605acc01` 和 `c716af8c`，均聚焦 `expat/lib/xmlparse.c`。

以下数据来自 OpenHarmony 四个目标文件，分别执行 `-fsyntax-only` 语法检查和 `-Xclang -ast-dump=json` 提取。计时仅包含对应命令的执行过程。

## 3. 内存与 CPU 占用

Expat 第 2 次运行中，各容器的内存采样最大值如下。代码分析、编译和 ASan 程序执行均在 cxx-analyzer 容器内完成。

| 容器 | 主要任务 | 内存采样最大值 |
|---|---|---:|
| lima | API 服务、任务编排和智能体分析 | 64.5 MiB |
| cxx-analyzer | 代码分析、编译和沙箱执行 | 314.8 MiB |
| postgres | 任务与结果存储 | 39.8 MiB |
| redis | 缓存与队列服务 | 10.3 MiB |

cxx-analyzer 的内存采样最大值为 314.8 MiB，配置上限为 2048 MiB；同次运行的 CPU 采样最大值为 167%。Docker 的 CPU 百分比按多核使用情况累计，因此可超过 100%。

四个容器各自的内存采样最大值之和约为 429 MiB。这些最大值可能出现在不同时刻，不能作为整个平台同一时刻的内存峰值。容器内存采用 Docker 的 MemUsage 统计值；前表的 RSS 则是进程内存统计，两者分别列示。

## 4. 代码规模与资源配置

仓库文件数量与实际送审范围共同决定扫描开销。一次包含 16 个 C/C++ 翻译单元的任务，在发现窗口上限为 8 的配置下调用模型 8 次，20 秒后以无可审查线索结束。该任务耗时对应受窗口限额约束的处理过程。指定重点路径后，平台可将模型调用集中到待分析文件，再对候选问题执行沙箱验证。

大型 C++ 文件的预处理数据也会增加资源开销。ResInsight 源码测试中，包含较多头文件的单个翻译单元产生了约 100-407 MB 的 AST JSON。因此，大型仓库的部署配置需要同时考虑源码快照大小、AST 输出、编译内存和任务时限。

`deploy/competition/README.md` 提供的资源配置建议如下：

| 配置项 | 默认值 | 大型仓库建议值 |
|---|---:|---:|
| 快照文件数上限 | 5000 | 50000 |
| 快照单文件大小上限 | 512 KB | 4 MB |
| 快照总大小上限 | 20 MB | 2 GB |
| 分析超时 | 300 s | 900 s |
| 分析容器内存上限 | 2 GB | 8 GB |
| 分析容器进程数上限 | 128 | 512 |

这些参数用于设置任务可使用的资源，与前述实测耗时和内存数据分别记录。部署时可根据仓库规模、头文件依赖和分析目标调整限额。
