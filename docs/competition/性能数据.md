## 4. 容量边界（实测引用）

- **AST dump 规模**：真实头文件重的 C++ 单 TU `-ast-dump=json` 实测达
  **100–407 MB**（ResInsight 真实路径，容器内 clang-14 实测，采集脚本
  `.superpowers/tmp/measure_dumps.sh`；记录见
  `docs/COMPETITION_VALIDATION.md` §2.1 战果 3）。产品上限
  **16 MiB**（`MAX_AST_JSON_BYTES`，`cxx_analyzer/uaf_scan.py:67`），超限
  TU 服务为不可用并记 coverage gap；按函数过滤的提取策略在 backlog。
  同类大 TU 上 `-detailed-preprocessing-record` 可直接使 clang-14 崩溃
  （实测记录）。
- **快照清单限额**（默认 → 参赛 profile，`deploy/competition/README.md` §1）：

  | 变量 | 默认 | 参赛建议 |

  | `LIMA_REPOSITORY_SCAN_MAX_FILES` | 5000 | 50000 |
  | `LIMA_REPOSITORY_SCAN_MAX_FILE_BYTES` | 512 KB | 4 MB |

  `MIN_FREE_BYTES` ≥512MB（`.env.competition.example`）。

## 5. 性能设计（设施语义与验证）

- **缓存**：`lima/agent_scale.py` `ResultCache`。合同测试
  `tests/test_agent_scale.py:347` `test_orchestrator_cache_roundtrip`：
  首轮 `{"hits": 0, "misses": 1}`；第二轮换上"任何 LLM/实验调用即失败"的
  守卫传输与守卫工作台，测试通过即证明目标结果整体来自缓存——**命中即
  零 LLM 调用、零沙箱实验**。键含 snapshot_hash + 目标全字段 + 模式 +
  对话轮数；坏条目按未命中自愈。
- **并行**：`map_bounded` 有界线程并行。测试断言 `sequential == parallel`
  整对象相等（结果恒按确定性 Scout 序聚合，并行只影响墙钟）。
- **增量**：`detect_changed_files` 三方差异（新增/修改/删除）为接口基础；
  按文件粒度自动增量重跑为预留（缓存键锚定整快照指纹，任何变更换指纹
  全量重算——快照身份贯穿的直接后果，`deploy/competition/README.md` §6）。
- **采集设施**：`PlatformReviewStats`（目标数/实验数/Scout/Specialist/
  Critic 调用数）与实验台账逐轮 stage/exit/error_type 随报告输出；
  评测报告 `latency_seconds`/`elapsed_seconds` 为真实耗时。
