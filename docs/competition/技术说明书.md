## 1. 系统概述

### 1.1 五层漏斗架构

平台把漏洞检测组织为一条从全量代码到可复现报告的漏斗。上层便宜、高召回；
越往下越贵、越精确；一切漏洞结论产生于智能体，终极裁决来自沙箱内的真实执行。

```text
第0层 静态分诊（仪器：望远镜）
  语义检索（分配/释放/长度 API/调用邻域种子，lima/cxx_retrieval.py）与
  漏洞包种子模式在全量代码上运行。产出"线索"（lead）而非结论；
  便宜、高召回，智能体可随时推翻。
        ↓ 召回面向全量
第1层 侦察筛选（Scout 智能体，lima/agent_scout.py）
  有界只读工具（搜索/读码/调用关系）自主排查线索：
  grep→读→追→排除→升级可疑度，产出带理由的目标清单与留痕的排除记录。
        ↓
第2层 深度分析（Specialist 智能体 + Critic，lima/uaf_llm_branch.py）
  深读代码，追别名链/生命周期/数据流，形成结构化漏洞假设
  （触发条件、触发路径、CWE、PoC 驱动代码、实验设计、未决假设）；
  Critic 对抗审查，主动寻找反证并引导修正。
        ↓
第3层 复现工作台（lima/agent_repro_tools.py → cxx_analyzer/repro.py）
  智能体编写 PoC 驱动，经 compile_and_run_asan 在五层沙箱内
  clang++ -fsanitize=address 编译并运行；读结构化 ASan 报告与假设比对：
  命中同一身份 = runtime-confirmed；不命中 = Critic 引导修正假设重来
  （受 dialogue_rounds / 预算约束）——假设-实验-修正闭环。
        ↓
第4层 定稿（Reporter 智能体 + 数据挖掘，lima/agent_report.py、
  lima/impact_mining.py、lima/agent_patch.py）
  CVE 离线匹配、git 影响范围（引入提交/分支传播/版本范围）、
  补丁建议 + PoC 回归验证、eRST 式漏洞研究档案。
```

### 1.2 智能体主体哲学

设计文件 `docs/superpowers/specs/2026-09-12-agent-vuln-platform-design.md`
§1/§9 的核心倒置已在实现中固化（`lima/agent_orchestrator.py` 模块 docstring，
第 1–47 行）：

- **智能体是检测主体**。没有绑定 Scout 目标的 Specialist 假设就不存在
  Finding；静态分诊与确定性组件只作为"仪器"给假设评级，不直接产生结论。
- **确定性组件是仪器不是关卡**。UAF v2 的事实提取、P1–P7 证明引擎、Broker、
  状态机保留为可咨询工具；PASS/REFUTED 作为证据进入裁决，永不前置放行
  （原 v2 proof-before-LLM 编排与 UNKNOWN-only 门控已在平台编排落地时退役）。
- **PoC 是跑出来的，不是写出来的**。报告中的 PoC 必须附带真实执行记录。
- **误报保守**。无实证发现按低等级汇报，不冒充确认；非内存安全类问题由
  假设合同的封闭 CWE 词表拒绝，不计入安全漏洞。
- **全程可审计**。每次线级调用、每次实验都有预算扣减、台账与降级记录。

## 2. 关键技术原理

### 2.1 五层沙箱（执行边界）

实现：`cxx_analyzer/sandbox.py`（490 行）、`cxx_analyzer/execution.py`、
`docker-compose.yml` / `.github/workflows/ci.yml` 的容器安全参数。

| 层 | 机制 | 实现位置 |
|---|---|---|
| 1. 容器边界 | 只读根文件系统 + `cap-drop ALL` + `no-new-privileges` + 非 root uid（10002）+ 仅内网 | `ci.yml` 容器测试与 `docker-compose.yml` |
| 2. Landlock 文件系统访问控制 | fail-closed：`landlock_abi()`（sandbox.py:214）探测 ABI，低于 `MIN_LANDLOCK_ABI=3`（:33）即拒绝启动；`apply_landlock()`（:328）按 `SandboxPolicy` 白名单授予读/写/执行 | `cxx_analyzer/sandbox.py` |
| 3. seccomp 进程隔离 | `apply_process_isolation()`（:377）按架构（x86_64/aarch64/riscv64）安装 BPF 过滤器，封锁 kill/ptrace/tgkill/unshare/setns/clone3/process_vm_* 等同 UID 进程控制系统调用；`prlimit64` 仅允许目标 pid=0（自身） | `cxx_analyzer/sandbox.py:149` 起的封锁表 |
| 4. 身份与环境清洗 | 非 root 运行；`clean_environment` 剥离环境密钥，分析用固定清洗环境（`SANITIZER_ENVIRONMENT`：clang-14、`-fsanitize=address -fno-omit-frame-pointer -g`、`ASAN_OPTIONS=abort_on_error=0:detect_leaks=0:color=never`） | `cxx_analyzer/execution.py:19` 起 |
| 5. 预算与限额 | 分析请求级 deadline（`cxx_analyzer/deadline.py`）、单步/总体超时、输出字节上限、argv 步数与字节数上限（`cxx_analyzer/config.py`：MAX_STEPS=64、MAX_ARGUMENTS_PER_STEP=128、MAX_ARGUMENT_BYTES=4096）、快照清单三限额（文件数/单文件/总量） | `cxx_analyzer/config.py`、`lima/config.py` |

要点：

- **模型生成的 PoC 驱动与被测仓库代码进同一座监狱**。复现工作台两步
  （编译、运行）都走 `cxx_analyzer.execution.run_step` 这个 fail-closed
  Landlock 启动器，无直接 subprocess（`cxx_analyzer/repro.py` 模块 docstring）。
- **fail-closed 握手**：能力探针（Landlock ABI、seccomp 可用性、非 root、
  网络 namespace、只读挂载等）缺一即拒绝执行；受信构建生成门禁
  （`cxx_analyzer/trust.py`）同样按探针清单 fail-closed，管理员总门禁
  `LIMA_CXX_TRUSTED_BUILD_CONTEXT_GENERATION` 无法被分析请求、仓库内容或
  模型输出影响。沙箱只调"房间大小"（限额参数），五层锁不放宽
  （`deploy/competition/README.md` §1/§3）。
- Linux 专属：Landlock/seccomp 是 Linux 内核机制，宿主开发在 Windows 上跑
  Fake 层测试，容器实证层在 Linux 容器内完成（见使用说明书"容器内测试"）。

### 2.2 确定性上下文管道（快照指纹 / Build Context / clang 事实 / 身份派生）

实现：`lima/uaf_models.py`（659 行）、`cxx_analyzer/build_context.py`（923 行）、
`cxx_analyzer/uaf_scan.py`（1051 行）、`lima/workspace.py`。

- **快照身份贯穿**：`RepositoryWorkspace.inventory().fingerprint()`
  （lima/workspace.py:75/:168）从快照清单派生 `snapshot_hash`；分诊、事实、
  实验、报告与结果缓存全部锚定该指纹。C/C++ 源扩展白名单含
  `.inl/.ipp/.tpp` 内联实现头（workspace.py:17–18 与
  `cxx_analyzer/snapshot.py` 两处镜像）。
- **Build Context Resolver**（build_context.py 模块 docstring）：只回答
  "该编译单元的编译语义是否被受信构建上下文钉死"。默认路径永不执行仓库
  构建系统（CMake/Make/Ninja 等一律不执行，`CMakeLists.txt` 是不可信数据）；
  只消费已存在的 `compile_commands.json`，argv 逐项过
  `validate_compiler_argv` 校验（拒绝 response file、`-Xclang -load`、路径
  逃逸），任何拒绝/歧义/缺路径降级 `incomplete`。`context_hash` 只对
  `resolved` 上下文存在，哈希的是语义参数投影（`-I/-D/-std` 等），非语义
  输出旗标不漂移身份。heuristic 上下文恒为 `incomplete`，永不 fact-verified。
- **clang AST / 受限 CFG 事实提取**（uaf_scan.py 模块 docstring）：
  审计过的 clang-14 以 `-fsyntax-only -Xclang -ast-dump=json` 加
  `-Xclang -detailed-preprocessing-record` 经沙箱执行器运行，只转发 resolver
  的语义参数。产出 11 类线格式事实（allocation/release/dereference/
  member-access/alias 等）；支持的 CFG 语法是封闭白名单（直线、嵌套
  if/else、无副作用的短路运算符），白名单外一律记 coverage gap 并
  `cfg_complete=False`，不为不支持的构造编造事实。AST dump 上限
  `MAX_AST_JSON_BYTES = 16 MiB`（uaf_scan.py:67）；缺失/截断/不可解析的
  dump 使该单元以 `extraction: unavailable` 服务。AST dump 无 Clang USR，
  `function_usr` 为合成键并每次记录 `usr-synthesized`——下游 PASS 无真实
  USR 即禁止。
- **身份派生**（uaf_models.py 模块 docstring）：`CandidateIdentity` 是唯一
  合法复合运行身份，所有 map/set/cache 键必须走
  `(snapshot_hash, candidate_id)` 复合键 `as_key()`；`derive_object_id` /
  `derive_candidate_id` 对规范化材料元组做 JSON 规范哈希，插入无关分配
  不会漂移既有身份。证据等级取自冻结的
  `lima/contracts/evidence.py`（EvidenceLevel D0–D4、EvidencePolarity，
  :221–:228），不存在混合枚举。`ProofReadiness` 定义 fact-verified 的必要
  条件：resolved 构建上下文 + 完整 AST/CFG 提取 + 无关键 coverage gap。

### 2.3 智能体角色与严格 JSON 合同

角色清单与合同（`lima/uaf_llm_branch.py:101–102`、模块 docstring；
`lima/agent_scout.py` 模块 docstring）：

- **Scout**（侦察筛选）：输入只有线索 id、位置、摘要、分诊种子与经注入的
  快照读取器读出的有界代码片段；一切不可信内容经 `ascii()` repr 风格转义
  并先截断后转义，控制字符/换行/非 ASCII 不进上下文；标签、CVE 标识、
  ground truth 无通路。输出是封闭形状 JSON 数组（每条线索恰有
  `lead_id/verdict/reason/confidence` 四字段）；**判决被重新绑定到在册线索
  记录，回复永远改不了线索的身份、路径、行号**。未提供的 `lead_id` 是伪造
  引用，整批拒收且不修复；未被判的线索保持 pending 重排，不粉饰成排除。
- **Specialist（memory-lifetime-specialist）**：产出六字段封闭 JSON——
  `target_id/hypothesis/trigger_path/cwe/driver_code/experiment_design/
  unresolved_assumptions`。回复只能引用在册 `target_id` 与已提供的事实 id；
  **伪造 id 整轮拒收且不修复**（uaf_llm_branch.py:153 定义
  AuthorizationViolation 类失败，区别于可修复的格式失败）。
- **Critic（adversarial-critic）**：对假设对抗审查，产出
  `assessment/rationale/revised_driver_code`；`revise-experiment` 引导下一轮
  修正实验，`hypothesis-wrong` 否决假设。
- **伪造拒收 / 一次修复纪律**：格式失败允许恰好一次修复
  （uaf_llm_branch.py:495 `send_semantic_request`："one strict reply round
  with exactly one format repair"）；授权失败（伪造 id）、传输失败、预算
  耗尽永不修复。温度固定 0，提示词模板标识
  `lima-cxx-agent-system-v1` 进入报告身份清单。
- **验证状态由确定性代码写入**：共识、工具证据绑定与 source-mode 上限由
  代码计算，永不由模型投票产生；模型回复在任何合同下都发不出
  `fact-verified/tool-corroborated/runtime-confirmed`。

### 2.4 复现工作台（ASan 编译运行 / 报告结构化解析 / 渲染噪声重试）

实现：`cxx_analyzer/repro.py`（Task 1 版本化 `/v1/repro` 端点），
工具封装 `lima/agent_repro_tools.py`（工具名 `compile_and_run_asan`），
模板 `lima/repro_templates.py`。

- **一次调用 = 一次沙箱内 clang++ -fsanitize=address 编译并运行**。驱动与
  二进制放在快照的可写 build root，驱动按内容哈希命名 stage，实验可复现
  且不碰撞；编译器与二进制只读已核验源码树。
- **报告结构化解析永不猜**：`parse_asan_report` 要求完整自洽的 ASan 报告
  （ERROR 行 + 匹配 SUMMARY 行），否则返回 None。结构化输出包含错误类型、
  faulting frame 行号、freed-by / allocated-by 栈、截断标记、编译诊断。
- **渲染噪声重试**：受限非 root 容器下 clang-14 的 ASan 运行时有已知渲染
  崩溃类问题（SIGSEGV 且无任何报告输出，容器实测约 30% 概率，计划 Task 1
  实施记录）。产品行为（`cxx_analyzer/repro.py:378` 起 docstring）：SIGSEGV
  且无可解析报告不构成"无漏洞"裁决，原地重试至多两次（共三次尝试，共享
  请求 deadline、每次尝试独立 step 预算），全部为噪声时 `ok=False` +
  `asan-runtime-segv-retried` 诊断；其余退出码保持单次行为。
- **工具层纪律**（agent_repro_tools.py 模块 docstring）：参数校验复用
  Task 1 规则，被拒请求不触网不扣预算；预算时序与线级调用一致（调用数 +
  请求字节先行扣减不退还，响应字节到达时扣减）；线上来的所有文本
  （诊断、错误类型、raw_tail）repr 风格转义后再截断；
  `CxxAnalyzerUnavailable/ProtocolError` 降级为有界 `transport-failed`
  观察而非异常穿透智能体循环。stage 词表封闭：`compile/run/transport-failed`。
- **PoC 驱动模板**：`DRIVER_TEMPLATES`（repro_templates.py:160）提供六类
  最小骨架——`heap-uaf / double-free / heap-overflow / null-deref /
  integer-overflow / generic-call`，占位符为封闭词表
  `{{HEADER_DECL}}/{{TARGET_FUNC}}/{{TARGET_ARGS}}`，纯字符串替换、零副作用；
  模板只是起点，智能体可完全自写驱动，两者进同一沙箱同一预算。

### 2.5 假设-实验-修正闭环（平台编排）

实现：`lima/agent_orchestrator.py`（1465 行）`run_platform_review`，模块
docstring 即冻结语义；仓库扫描器唯一接线点 `lima/repository_scanner.py:665`。

一轮目标的生命周期：

1. Scout 目标 → Specialist 结构化假设（含 PoC 驱动）→ 复现工作台执行；
2. **runtime-confirmed 只能来自已执行的 ASan 实验**（run 阶段 ok）且错误
   类型匹配假设的 CWE bug 类；观察作为 (D3, SUPPORTS) Broker 判决绑定。
   干净运行、传输失败或不同 bug 类都封顶在 `semantic-supported`
   （(D1, SUPPORTS)）或 abstain；
3. 不命中 → Critic 引导修正（新驱动/修正假设）→ 再实验。修正轮数受
   `dialogue_rounds`（首轮实验后每目标至多 N 轮）与共享 `CxxAgentBudget`
   约束；预算耗尽是记录在案的降级（auto）或任务失败（required）；
4. 证明仪器至多咨询一次（存在已核验事实与匹配候选时）：PASS 评级
   `fact-verified`，REFUTED 评级 `rejected`（仅审计，永非 Finding）；
   REFUTED 证明 + 强支撑运行时证据强制 `needs-human-review`（冻结仲裁
   规则 1，`lima/uaf_orchestrator.py:210` `arbiter_state`）；
5. Diff-only source mode 永不跑沙箱实验，一切正向声明封顶
   `semantic-supported`——没读过的代码不能复现。

模式矩阵：`off` 零调用空转；`auto` 一切 LLM 失败降级为记录在案的
abstention（实验失败是信息不是失败）；`required` 在 LLM/配置失败时任务
直接失败，绝不以"无漏洞"冒充成功。实验结果按确定性 Scout 序聚合。

### 2.6 证据等级与状态机

- 证据正交轴：`EvidenceLevel` D0–D4 × `EvidencePolarity`
  （`lima/contracts/evidence.py`，EvidenceLevel:221、EvidencePolarity:231）。
- **三态 Evidence Broker**（`lima/uaf_broker.py` 模块 docstring）：对同一
  候选身份与同一生产者只回答 `support | contradict | no-evidence`，并携带
  证据自身的等级/极性两个独立序列化字段——判决不蕴含固定 D 级，等级也
  不反推判决。`contradict` 需同时满足五个条件（精确候选身份、完成的生产
  run、有效 tool_run_id 溯源、至少一条 REFUTES 记录、ProofResult 至少一个
  refuted obligation）；`BROKER_IS_NOT_CONTRADICTION` 冻结七种永不构成
  反证的情形（无报告、未覆盖、生产者未运行、同位置异 CWE、模糊位置、
  缺 run 身份等）——空结果永远不是安全证明。
- **终态词表**（`lima/uaf_orchestrator.py:91–109`）：
  Finding 状态 = {semantic-supported, fact-verified, tool-corroborated,
  runtime-confirmed, needs-human-review}；正向状态集不含
  needs-human-review。`runtime-confirmed` 仅实证可达（已执行 ASan 命中）；
  `fact-verified` 仅确定性证明可达。verified 门禁只放行四个已验证状态，
  `automatic_repair` 恒 false（C/C++ Finding 永不自动修复）。

### 2.7 规模化（缓存 / 有界并行 / 增量基础）

实现：`lima/agent_scale.py`（238 行，三个无依赖设施），编排接入
`run_platform_review(parallelism=, cache=)`（agent_orchestrator.py docstring）；
合同测试 `tests/test_agent_scale.py`（`test_orchestrator_cache_roundtrip`，
:347 起）。

- **ResultCache**：文件缓存，键 = 命名空间 + 调用方指纹（调用方必须把
  `snapshot_hash` 与目标全字段、模式、对话轮数折进指纹）；条目原子写入
  （tmp+rename），坏条目按未命中处理并删除（缓存永不毒化运行）。命中即
  零 LLM 调用、零沙箱实验——roundtrip 测试用"守卫传输/守卫工作台在第二次
  运行中任何调用即失败"证明回放确实来自缓存。`cache=None`（默认）行为与
  无缓存完全一致。
- **map_bounded**：独立目标在受控线程内并行；结果恒按 `order_key`
  （确定性 Scout 序）聚合而非完成序——并行只影响墙钟不改输出序，测试
  断言 `sequential == parallel` 整对象相等。异常收集为 `ScaledFailure`
  记录，不吞异常，失败语义归调用方。
- **detect_changed_files**：两份 `{path: sha256}` 清单的纯三方差异
  （新增/修改/删除），是"仅变更文件重跑"的数据基础。按文件粒度的自动
  增量重跑为接口预留：缓存键锚定整快照指纹，任何文件变更都会换指纹全量
  重算——这是快照身份贯穿不变量的直接后果
  （`deploy/competition/README.md` §6）。

## 3. 漏洞类型包插件架构

实现：`lima/vuln_packs/__init__.py`（97 行，接口）+ `lima/vuln_packs/memory.py`
（93 行，内存包）。设计 §4 的落地形态：

- 平台内核（编排/工具/复现工作台/证据等级/报告）**类型无关**。每种漏洞
  类型一个冻结 `VulnPack` dataclass，携带设计的五类资产：Specialist 知识
  附录、分诊种子模式、PoC 驱动模板名、ASan/UBSan 判读规则、CWE 映射。
- **包是数据不是行为**：本模块零执行；匹配语义留在消费方（编排器把
  marker 子串对小写化的 sanitizer 错误类型匹配；分诊层把种子正则对源码
  匹配）。`runtime_markers()` 是编排器消费的唯一派生视图
  （CWE→marker 子串表）。
- **内存包六 CWE**（memory.py）：CWE-416 释放后使用、CWE-415 双重释放、
  CWE-787 堆越界写、CWE-125 越界读、CWE-476 空指针解引用、CWE-190 整数
  溢出致内存破坏。前四类逐字搬移自编排器包前的硬编码（行为保持），后两类
  为包化扩展。marker 数据跟随 sanitizer 自己的词表：ASan 把空解引用报为
  `SEGV on unknown address ...` 而非命名堆错误；整数溢出本身是 UBSan 诊断
  （`signed-integer-overflow` 等），故 CWE-190 无纯 ASan marker——回绕尺寸
  造成的堆越界按 ASan 报告绑定 CWE-787/125，永不冒领 CWE-190。
- 新增一个包（信息泄露、注入等）= 数据 + 一次 `register_pack` 调用，
  永远不是内核改动。

## 4. 与传统 SAST 工具的定位差异

| | 传统 SAST（模式/数据流静态扫描） | 本平台 |
|---|---|---|
| 结论来源 | 规则命中即报告 | 智能体假设 + 沙箱内 ASan 实证 |
| PoC | 无（或模板猜测） | 智能体编写、真实编译运行、附执行记录与 PoC 稳定性统计 |
| 误报处理 | 靠规则调优 | 无实证不出"确认"（状态机封顶）；Critic 反证；非安全类封闭词表过滤 |
| 静态分析的角色 | 检测主体 | 仪器：分诊分配注意力、事实/证明供咨询、给假设评级 |
| 可审计性 | 告警列表 | 每次线级调用/实验有预算扣减、实验台账、降级诊断与封闭诊断词表 |
| 修复建议 | 模式替换 | 智能体补丁 + 应用补丁后重跑 PoC，不再触发才标"验证通过" |

## 5. 报告与数据挖掘（第 4 层，已实现事实）

- **eRST 式档案**（`lima/agent_report.py`，596 行，中文 Markdown）：七节
  （0 元数据/1 档案/2 目标环境/3 技术分析/4 复现/5 影响/6 修复与披露）。
  诚实不变量："已通过 ASan 物理验证"字样仅在 Finding 自身实验台账含已执行
  且命中的 ASan 实验时可达，裸 `runtime-confirmed` 标签无台账时在报告边界
  降级"待复核"（无实证不写"已验证"）；证据比例化严重级
  （runtime-confirmed/fact-verified→高危，tool-corroborated→中危，其余→低危）；
  CVE 匹配是本地索引三键严格匹配（组件前缀 + fnmatch 路径 glob + 提交窗
  重叠），无匹配输出"暂无对应公开 CVE（待评审）"，永不臆测；索引是运维
  提供数据（NVD/CVE 下载），模块零网络。不可信文本渲染在长度自适应的
  fenced code block 内，数据不能破栏。
- **git 影响挖掘**（`lima/impact_mining.py`，409 行）：引入提交（blame）→
  分支传播（branch --contains）→ 版本范围（tag --contains）。红线：git 子
  命令首词白名单（blame/branch/log/rev-parse/show/tag），写命令在派生进程
  前拒绝；argv 纯字符串列表 shell=False；每次调用限时 30s；禁全局/系统
  git config（别名无法重写命令）；autocrlf 漂移重试一次；缺文件/未跟踪/
  越界行诚实返回 None，永不编造邻近答案。`known_commits` 喂给档案的 CVE
  提交窗。
- **补丁建议 + PoC 回归验证**（`lima/agent_patch.py`，763 行）：补丁工程师
  模型产出整文件替换版（不收 unified diff——沙箱无 patch 工具，合同上不
  可能半应用），应用到**每请求临时隔离副本**（原快照与原仓库永不写入），
  原样重跑 PoC。`PatchVerification(verified=True)` 由构造器强制要求
  `compiles=True and poc_still_triggers=False`——五种诚实失败（编译失败/
  PoC 仍触发/PoC 触发了别的缺陷/渲染噪声/其他非结论性运行）永不猜成
  "已验证"；模型文本永不作为证据；`target_path` 永不来自模型。

## 6. 已知局限（诚实清单）

1. **第一阶段支持范围（UAF 确定性事实/证明仪器）**：同函数、同 TU 的
   new/delete 与 malloc/free、`*p`/`p->m` 后继使用、有限 alias-copy 链；
   受限 CFG 只覆盖直线与单层/嵌套 if/else。循环、switch、goto、异常、
   lambda、协程、模板/宏命中关键范围、跨 TU、自定义 allocator、并发等
   一律 coverage gap 或 UNKNOWN，降级不隐瞒（`semantic_gaps` 逐项进报告）。
2. **AST 规模边界**：真实头文件重的 C++ 单 TU `-ast-dump=json` 实测可达
   100–407 MB，产品上限 16 MiB（`MAX_AST_JSON_BYTES`，uaf_scan.py:67）；
   超限 TU 服务为不可用并记 gap。按函数过滤的提取策略在 backlog
   （`docs/COMPETITION_VALIDATION.md` §2.1 战果 3）。
3. **真实模型平台链端到端未验证**：`run_platform_review`（Scout→假设→
   实验→修正→裁决）在真实 LLM provider 上的运行尚未执行；配对基准的
   Fake 全绿不推断真实模型表现（`docs/COMPETITION_VALIDATION.md` §1 状态表）。
4. **真实容器 ASan 平台链未验证**：平台评测内工作台是脚本化替身；经
   `/v1/repro` 的真实 clang-14/ASan 容器实证对平台链的贯通（D3 路径的
   端到端 witness 绑定）未在本环境执行。`/v1/repro` 端点自身的容器单测
   （正例三驱动 + 超时/输出爆炸/路径逃逸负例）已在计划 Task 1 容器层通过。
5. **评测基准是合成与钉死对**：`evaluation_data/platform_cases/` 的 6 组
   对是本仓库自有合成样例（Apache-2.0，逐文件 SHA-256 钉死）；合成对不
   测量生产检测能力，报告内逐条携带该有效性边界。
6. **评测的 Sidecar 半边是罐装 wire**：平台评测的事实来源是按 case 罐装的
   `/v1/uaf-facts` 形态；真实 Clang 提取行为由容器测试与真实环境验收单独
   覆盖，两者分别标注、不互相冒充。
7. **LLM 用量是字节代理**：不读 provider token 计数，`cost_usd` 恒 null；
   报告口径为下界视图。
8. **性能数据边界**：全仓性能数据来自合成基准与 6 案例 Fake 评测；真实
   模型平台链耗时、OpenHarmony 全仓性能均未验证（见 `性能数据.md`）。
