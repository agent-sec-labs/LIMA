# LIMA 容器自动构建：赛后开发计划

日期：2026-10-19。排期属性：**赛后开发，不纳入本届比赛提交或代码冻结门禁**。
本计划仅安排后续开发及 GitHub 任务，不在本次启动功能实现、真实模型调用或生产环境变更。

## 用户目标

普通用户只提供仓库、提交版本和分析范围，不需要准备 Dockerfile、构建配方、编译数据库或手工执行 Docker 命令。
用户可选择“仅扫描”或“构建后分析”；平台匹配适用的已验证配方，无配方时进入受预算约束的构建规划流程。
平台负责隔离构建、测试、产物核验、编译上下文传递、PoC 编译执行和证据报告。无法适配时明确失败或需要协助，不能静默跳过构建再声称完整验证。

```text
用户提交仓库/版本
  → 后台构建任务
  → 配方匹配
      → 命中：校验版本和功能范围
      → 未命中：智能体生成候选配方并有限修正
  → 独立构建 Worker：初始化/配置/编译/测试/安装/验证
  → 核验并登记产物
  → 构建上下文转换与绑定
  → 代码分析/候选问题/PoC 编译运行
  → 报告、失败诊断及覆盖范围
```

## 已有基础与边界

- 本地已有 `lima/container_build.py`、`deploy/build-recipes/{resinsight,opm-common}/Dockerfile` 和 `full-build.json`。
- CLI 在本地实跑：ResInsight 1139 项已启用 GoogleTest 通过，35 项 disabled；opm-common 213 项 CTest 通过。此为固定配置的工程验证，不代表任意仓库、完整 GUI、所有可选功能或 OpenHarmony 原生构建通过。
- 前端提交任务尚未调用完整构建入口；也不会自动把构建依赖与链接配置交给 PoC 容器。
- GitHub #181 跟踪构建/分析两层架构与上下文包；#182 跟踪大仓库 compdb 预算问题。#269 已完成双版本 checkout 校验。后续应复用相关实现，不因新增 Epic 自动关闭或重排旧任务。
- 本地实现和运行证据不等于已经合入 GitHub main。实施前须重新核对 main、未合并 PR、工作区和相关 Issue。

## 分阶段交付

1. **已有配方闭环**：完成 B01/B02/B03，前端可触发已适配仓库的真实构建并查看结果。此阶段不能宣称自动适配陌生仓库。
2. **自主适配**：完成 B04，先支持 CMake；未命中配方时可生成、执行、有限修正并保留失败证据。
3. **构建到 PoC 的完整连接**：完成 B05/B06，真实构建上下文进入分析沙箱，证明项目依赖在 PoC 链路中确实被消费。

多智能体开发可让前端、后台、规划智能体在接口冻结后并行，主代理负责合同、合并和独立验收。共享 API/schema/编排文件同一时刻只由一个实施者修改；代码审查与最终真实验收不能用 Mock 代替。
不据此前的粗估承诺固定完成日期，赛后按接口评审和首个闭环实测重新估时。

## 全局完成标准

- 用户从浏览器提交受支持仓库后，无需人工命令即可完成构建到分析的操作路径；未适配状态明确可见。
- 复用固定源码、镜像 ID、配方哈希和构建配置身份，禁止跨版本/架构/编译器错误复用。
- 完整构建与 PoC 沙箱分开；项目构建成功不能冒充 ASan 确认。
- 智能体提出配方和修正，确定性执行器负责校验与结果判定；模型文本、普通退出码和普通崩溃不能独自证明漏洞。
- 失败、跳过、禁用、预算耗尽、环境不支持和成功分别统计；大仓库覆盖分母和未处理范围可查。
- 自动测试默认无付费模型调用；真实模型和目标代码的验收运行在独立资源上，费用和运行权限由部署配置控制。
- 每项有独立 PR、测试、可复现命令、证据位置和未验证边界；按 main/PR/本地分别记录状态。
