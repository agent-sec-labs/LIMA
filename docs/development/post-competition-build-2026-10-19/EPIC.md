## 用户目标

用户只提供仓库、版本和分析范围，无需准备配方、编译数据库或手动输入 Docker 命令。已有适用配方直接复用；未适配的 CMake 仓库由构建规划智能体提出配方并有限修正。平台持续展示构建/分析进度、失败原因和可下载证据。

## 已有基础与实施前检查

本地已有 `lima/container_build.py` 和 ResInsight/opm-common 的 `Dockerfile + full-build.json`，并留有真实构建证据；这不等于相关改动已经合入 GitHub main。开工先核对最新 main、未合并 PR 和现有实现，复用已有任务、认证、队列、日志、产物及 context-package 合同，不重建一套平行系统。

## 当前缺口

1. 前端任务创建尚未触发完整构建执行器。
2. 配方目前由人/Codex编写，平台不会自动生成和修正。
3. 完整构建环境中的头文件、宏、生成代码和链接依赖，尚未自动传递给分析与 PoC 工作台。

## 目标流程

仓库/提交 → 后台构建任务 → 匹配已有配方或生成候选 → 独立构建Worker → 配置/编译/测试/安装/验证 → 核验产物与上下文 → 分析/PoC编译运行 → 报告。

构建规划智能体负责提出配方和修正，确定性执行器负责执行、核验和判定。完整构建成功不能替代 sanitizer 验证或漏洞成立判断。
