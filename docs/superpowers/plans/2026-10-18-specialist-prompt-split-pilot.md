# Specialist 提示词拆分与小范围对照计划

> **执行说明：** 本文件为计划，不代表已实施或已取得效果。后续按任务逐项执行，可使用 superpowers:executing-plans；涉及正式交付时，遵守仓库 Implementation Packet 与冻结测试要求。

**Goal:** 在相同目标、模型和实验预算下，验证拆分 Specialist 提示词能否改善假设质量、PoC 合法性和漏洞版/修复版判别。

**Architecture:** 先做内容保持不变的结构拆分，再比较新的通用判据与机制卡。组件配方只在明确的已知组件复现任务中加载。继续沿用当前 Specialist → 实验 → Critic 链路及输出合同。

**Tech Stack:** Python 3.11+、pytest、现有模型调用、C/C++ ASan 隔离工作台。

**Spec:** 本次用户请求及关联聊天“介绍 LIMA 项目全貌”的已选范围；当前实现依据为 lima/agent_orchestrator.py、lima/vuln_packs/memory.py、scripts/run_platform_evaluation.py。

## 约束

- 本轮不接工具循环，不改 Discovery、Scout、Critic 提示词、六类 CWE 词表、验证状态机、预算策略或 sanitizer 配置。
- 不新增鉴权、信息泄露等漏洞包；CWE-190 不以普通 ASan 崩溃冒充整数溢出证明。
- 保留 Hypothesis 严格 Schema；“未证明”通过现有 unresolved_assumptions 和真实失败状态表达，不新增未经接线的结论类型。
- 当前工作区存在大量其他未提交修改；执行前登记基线及相关文件差异，禁止整体提交或覆盖其他任务文件。
- 实验标签、修复 diff、预期 CWE 和预期答案只留在评测侧，不进入模型输入；新旧版本使用相同中性路径。
- 10 月 20 日封包；10 月 19 日后半天停止扩写知识，给真实验证和回退留时间。

## 重点检查

1. 漏选机制卡：没有明确机制时加载全部通用机制卡；多机制允许组合，不提前锁死 CWE。
2. 配方泄漏：通用模式不含 Expat 特定触发组合；组件配方必须由可信运行配置显式选入。
3. 缓存串组：实际渲染提示词、知识内容及版本必须参与身份摘要；正式对照关闭结果缓存。
4. PoC 自造缺陷：驱动非法释放、重复销毁、关键路径桩替换等不能计作有效发现。
5. 虚假效果：模拟工作台只验证流程；有效性结论必须来自真实模型和真实隔离执行。

## 任务四：运行两组小范围对照

**拟新增：** scripts/run_specialist_prompt_pilot.py、tests/test_specialist_prompt_pilot.py；运行产物放 output/specialist-pilot/<run-id>/，汇总放 docs/competition/。

**实验分组：** A = 当前 legacy 全提示词；B = 新通用判据 + 固定四张机制卡，不加载组件配方。该对照评估整套提示内容调整，不能独立归因于减少配方或文本长度。

- [ ] 复用现有平台的记录结构和可重算指标；现有 run_platform_evaluation.py 继续承担离线流程回归。它的工作台按驱动 hash 模拟结果，即使用真实模型也不是实际 PoC 验证。
- [ ] 试验脚本通过可信配置选择 A/B，向同一真实工作台提交驱动，记录模型原始回复、解析失败、实验观察和各轮结论；测试使用替身检查标签隔离与预算一致。
- [ ] 冻结相同目标列表、代码片段、事实和构建条件，绕过上游重新抽样造成的候选差异，单独比较 Specialist；端到端候选覆盖留作另一次实验。
- [ ] 选择约 6 组配对案例：生命周期 2 组、越界 2 组、空值/错误处理 1 组、整数到内存大小 1 组。至少包含干净路径或已有防护的负例；整数案例只按当前可验证的内存后果计分。
- [ ] 优先复用现有样本，缺失机制再补最小对照。至少 2 组提前划为保留集，不在看到结果后继续调提示词；历史已调优样本只能标为回归集。
- [ ] 每组包含漏洞版与修复/负例版，各独立运行 3 次：6 × 2 × 2 × 3 = 72 次目标分析。先跑 2 组开发样本共 24 次，排除接线错误后再跑剩余 48 次；若改提示词，受影响开发结果作废重跑。
- [ ] A/B 交错执行，固定模型、参数及预算，支持时固定 seed；记录模型返回的实际用量，没有 token 数据则明确使用字节代理。
- [ ] 对每个候选 PoC 做两种检查：分别分析两版本是否误报；将漏洞版生成的同一驱动原样运行在两版本上。确需适配的 API 差异单独记录，不计作严格同驱动判别。
- [ ] 有效命中的驱动在两版本各重复执行 3 次，记录全量结果；编译失败、超时、环境失败独立分类，不能记作安全或静默剔除。
- [ ] Expat 已知配方案例单列复现回归，不进入未参与调优样本的有效发现统计。

**指标：** 有效且 API 合法的命中数/可验证正例数、同驱动版本判别数/已测试配对数、负例产生 Finding 数/负例数、非法 PoC 数/生成 PoC 数、Schema 失败、证据不足的表达、调用/实验/字节/耗时。同时报告总数、成功进入执行数和全部失败类别。
