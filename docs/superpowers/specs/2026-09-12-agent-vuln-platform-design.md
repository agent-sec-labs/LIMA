# 通用智能体漏洞挖掘平台设计（参赛 + 论文复用）

日期：2026-09-12
状态：待用户确认
目标分支：`codex/cxx-llm-agent-detection`
赛事：第五届中国研究生网络安全创新大赛·揭榜挑战赛题目1（OpenHarmony 开源代码漏洞挖掘）
论文方向：油气软件内存类漏洞检测（复用本平台内存漏洞包）

## 1. 定位与与前两个设计的关系

本设计是第三个阶段，定位为**面向赛事交付与论文复用的通用智能体平台**：

- `2026-09-02-cxx-llm-agent-detection-design.md`（阶段 B）：多 Agent 检测层。其 Agent 管线与
  有界工具成为本平台的第 1、2 层主体，直接复用。
- `2026-09-10-cxx-uaf-v2-design.md`（UAF v2）：确定性证明优先，服务于仓库自身审计要求。
  本平台**直接替换** v2 的"确定性优先"编排（用户决定，不做双链并存）：v2 的确定性
  组件降格为智能体可咨询的"仪器"保留（事实提取/协议/适配/身份/证据等级/Broker/
  P1–P7 证明引擎本身），v2 的编排脊柱（proof-before-LLM 路由、UNKNOWN-only 门控、
  scanner 双链接线）在平台编排落地后**退役删除**；其证据等级（D0–D4 + polarity）
  与状态机保留为智能体声明的裁判。
- 本设计的关键倒置：**智能体是漏洞检测的主体，静态工具是智能体的仪器**。
  静态分诊只负责在大规模代码上分配智能体的注意力，不产生结论；一切漏洞结论由
  智能体形成，由复现实验（ASan）终极验证。

## 2. 赛题要点映射（评价方式驱动设计）

| 赛题评分项 | 平台对应机制 |
|---|---|
| 准确性（误报扣分） | 验证等级保守汇报；无实证不出"确认"；非安全类问题过滤 |
| 完整性（漏报） | 静态分诊高召回 + 智能体侦察循环 |
| CVE/CWE 准确 | Specialist 假设强制绑 CWE；CVE 走离线库匹配，不做臆测 |
| PoC 可执行/稳定/可复现 | 复现工作台：PoC 不是"写出来的"而是"跑出来的"（ASan 实证闭环） |
| 分支影响分析 | git 历史挖掘：引入提交 → 分支传播 → 版本范围 |
| 修复建议 | 智能体补丁 + PoC 回归验证（补丁后 PoC 不再触发） |
| 工具性能 | 漏斗架构 + 并行/缓存/增量；性能数据入交付件 |
| 创新性 | 智能体自主实验复现 + 全程可审计证据链 |
| 类型多样性权重 | 漏洞类型包插件化 |

## 3. 总体架构：五层漏斗

```text
第0层 静态分诊（仪器：望远镜）
  语义检索 + 模式种子在全量代码上运行（便宜、高召回）
  产出"线索"而非结论；智能体可随时推翻
        ↓ 召回 ~全量
第1层 侦察筛选（Scout 智能体）
  有界只读工具（搜索/读码/调用关系）自主排查线索
  grep→读→追→排除→升级可疑度，产出带理由的目标清单
        ↓
第2层 深度分析（Specialist 智能体群 + Critic，按漏洞类型包分角色）
  深读代码，追别名链/生命周期/数据流，形成结构化漏洞假设
  （触发条件、路径、CWE 初判）；Critic 对抗审查找反证
        ↓
第3层 复现工作台（Reproduction 智能体）★核心竞争力★
  智能体写 PoC 驱动 → 调用 compile_and_run_asan → 读崩溃报告
  → 命中假设位置 = runtime-confirmed；不崩 = 修正假设回到第2层
        ↓
第4层 定稿（Reporter 智能体 + 数据挖掘）
  CVE 离线匹配；git 影响范围；补丁建议 + PoC 回归验证
  产出 eRST 式漏洞研究档案（= 赛题交付报告格式）
```

## 4. 漏洞类型包（赛题与论文的复用关键）

平台内核（编排/工具/复现工作台/证据等级/报告）类型无关。每种类型一个包：

- **内存漏洞包**（论文核心，做深做全）：UAF、越界读写、双释放（已有 Specialist/
  种子/基准）+ 空指针解引用 + 整数溢出致内存破坏（新增）。
- **竞赛扩展包**（按性价比补 2–3 个吃多样性权重）：候选为信息泄露、命令/路径注入、
  整数溢出（独立类）、空指针（独立类）。第一版不承诺全部。
- 每包构成：Specialist 提示与知识 + 分诊种子规则 + **PoC 驱动模板** + ASan/UBSan
  判读规则 + CWE 映射。
- 油气软件（OPM 系）与 OpenHarmony 只是两个接入仓库：快照/指纹/GitHub 固定 SHA
  通道复用。

## 5. 复现工作台（关键新组件）

### 5.1 职责

向智能体暴露实验仪器：`compile_and_run_asan(sources, driver_code, entry)`。

- 输入：目标源文件集合（依赖闭包抽取）+ 模型生成的 PoC 驱动代码；
- 执行：Sidecar 沙箱内 clang++ -fsanitize=address 编译并运行（五层沙箱原样适用：
  模型生成的 PoC 与被测仓库代码进同一座监狱）；
- 输出：结构化结果（编译诊断 / 运行退出码 / ASan 报告解析：错误类型、faulting
  frame、freed-by/allocated-by 栈、行号）；
- 实验台账：每次实验的输入、产物哈希、耗时、结论入账（供报告与回归验证）。

### 5.2 编译策略（三层）

1. **PoC 级**（主形态，现有即通）：驱动 + 相关文件直接编译运行；
2. **依赖闭包抽取**（推荐路线）：利用 compile_commands 能力把目标函数依赖闭包
   抽成最小可编译单元，绕开巨型仓库整仓构建；
3. **整仓构建**（特定情况）：参赛部署 profile 放开快照限额（文件数/单文件/总量）、
   加大 tmpfs 与内存、开受信构建门禁、离线依赖预处理（沙箱外拉好连同源码灌入）。
   沙箱五层锁不放宽，只调"房间大小"（均为部署参数）。

### 5.3 安全边界

- PoC 驱动是模型生成代码：与仓库代码同一沙箱、同一预算、同一审计；
- 驱动代码写失败不重试超过预算；编译产物/崩溃报告绑定快照哈希；
- 实验不可泄露环境密钥（环境清洗已有）。

## 6. 智能体编排 v3（对阶段 B 管线的改造）

- **Scout 自主循环**：线索清单 → 排查 → 合并/排除 → 目标清单。目标选取不再固定
  "路径序前 16"，由 Scout 决定（分诊仅给初始候选与理由）。
- **假设-实验-修正闭环**：Specialist 假设 → Reproduction 实验 → 不命中则修正假设
  重来（多轮，受 dialogue_rounds/预算/总 deadline 约束）；命中即升级证据。
- **确定性仪器可咨询**：UAF v2 事实/证明作为工具暴露（智能体可查精确事实），
  但不是前置关卡；其结果作为 D2 级证据进入裁决。
- 状态机沿用：runtime-confirmed（ASan 实证）> tool-corroborated > fact-verified
  （确定性证明）> semantic-supported > llm-candidate；verified 门禁与
  automatic_repair=false 不变。

## 7. 报告与数据挖掘（第 4 层）

- **报告智能体**：生成 eRST 式漏洞研究档案（用户模板即交付格式）：基本信息/概览/
  目标环境/技术分析/复现指南（编译命令 + PoC + ASan 日志）/影响与披露。
- **CVE 离线匹配**：本地 CVE 库（NVD 数据）按仓库/组件/时间窗/代码位置匹配，
  无匹配不臆测；新发现标注"待 OpenHarmony 安全奖励计划评审"。
- **git 影响挖掘**：引入提交定位（blame/log）→ 分支传播（branch contains）→
  影响版本范围；输出到报告"影响分析"节。
- **补丁建议 + 回归验证**：智能体出补丁，应用补丁后重跑 PoC——不再触发才算
  验证通过的修复建议（比纯文字建议更硬）。

## 8. 规模化（性能评分项）

- 并行：多个 (目标 × 实验) 在独立沙箱实例并行（parallelism 上限受控）；
- 缓存：快照指纹 → 分诊/事实/实验结果缓存（键含 snapshot_hash + 输入哈希）；
- 增量：仅变更文件重跑（依赖 compile_commands 变更检测）；
- 性能采集：耗时/内存/并行度自动入报告（交付件 5）。

## 9. 不可违反的系统不变量

1. 智能体是检测主体：分诊不得直接产出漏洞结论。
2. 实证优先：runtime-confirmed 只能来自沙箱内真实执行且命中同一身份。
3. PoC 是跑出来的：报告中的 PoC 必须附带其实际执行记录。
4. 误报纪律：无实证发现按低等级汇报，不冒充确认；非安全类问题（普通 DoS、
   健壮性 bug）过滤，不计入安全漏洞（赛题备注 3/6）。
5. 沙箱五层锁不放宽；模型生成代码与仓库代码同狱。
6. 快照身份贯穿：分诊/事实/实验/报告绑定同一 snapshot_hash。
7. 证据等级与 polarity 正交（沿用 contracts.evidence）。
8. 内存包行为在油气仓库与 OpenHarmony 上同构（仅仓库接入差异）。
9. 所有智能体输出过严格 JSON 合同；伪造事实/身份整轮拒收。
10. automatic_repair 恒 false。

## 10. v2 编排替换范围（明确化）

替换**编排**，保留**仪器**：

- **退役删除**：`lima/uaf_orchestrator.py` 的 proof-before-LLM 路由与裁决优先级
  编排、`lima/uaf_llm_branch.py` 的 UNKNOWN-only 门控（Specialist/Critic 不再等
  证明放行）、`repository_scanner.py` 的 uaf_v2 双链分支接线；对应编排测试改写
  为平台编排测试。
- **保留为仪器**：Build Context Resolver、clang 事实提取、`/v1/uaf-facts` 协议、
  Fact Adapter、CandidateIdentity、P1–P7 证明引擎（可调用工具，PASS/REFUTED 作为
  证据来源之一）、Broker、证据等级与状态机；仪器层测试原样保留。
- 退役在新编排（平台 Task 4）落地并回归通过后执行，同一提交内完成删除与接线
  切换，不留半死的并行模式。

## 10.1 非目标（第一版）

- 沙箱不开外网（依赖一律离线预处理）；
- 不承诺 OpenHarmony 整仓构建（走依赖闭包抽取）；
- 不承诺全类型覆盖（内存包为主 + 有限扩展包）。

## 11. 评测

- **配对基准扩展**：每漏洞类型包一套 vulnerable/fixed 配对（沿用现有评测框架），
  含"需要修正假设才命中"的样例（验证实验闭环）。
- **比赛指标映射**：准确性=配对 precision；完整性=召回；PoC 稳定性=同 PoC 重复
  运行 N 次全触发；性能=吞吐/耗时/内存采集。
- **论文侧验证**：内存包在油气仓库（OPM 系 + ResInsight）上运行，复用 eRST 档案
  格式输出，作为论文实验章节素材。

## 12. 冻结决定

- 智能体优先、工具为器的总体倒置；
- **替换（非并存）UAF v2 编排**：仪器保留、编排退役，单一智能体链；
- 五层漏斗与漏洞包插件化；
- 复现工作台为第一优先建设项；
- PoC 必须实证、误报保守汇报、非安全类过滤；
- 沙箱只调房间大小不松锁；
- 内存包 = 论文本体，仓库接入层差异化。

若实现与赛题细则或论文要求冲突，先更新本设计并获用户确认，不得静默放宽。
