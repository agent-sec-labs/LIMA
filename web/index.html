步骤 1 / 3

你希望审计什么？

完整仓库适合全面排查；PR Diff 适合上线前审查本次改动。

审查范围

只分析下一步粘贴的 Unified Diff，不读取完整仓库。

还没有准备仓库？加载内置的安全示例，完整体验审计与报告，不会连接外部服务。

步骤 2 / 3

确认审计范围

系统将使用默认工程基线扫描仓库，不执行目标代码。

推荐安全基线AST 规则 + 跨文件数据流 + 可用时的 SAST 证据融合

推荐
  • CWE-22 路径遍历与包含关系
  • CWE-78 命令注入与 shell 边界
  • CWE-89 SQL 注入与结构化 token
  • 危险反序列化、敏感信息与认证误用

步骤 3 / 3

检查后开始审计

确认目标和安全边界。提交后可离开页面，任务会在后台运行。

你将看到什么？报告会按风险等级列出问题、代码位置、证据状态、自然语言解释和修复建议。JSON 仅保留在 API 层，不作为网页展示。
